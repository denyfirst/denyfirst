What this
keeps.

A count of scans, and nothing else. Not the hostname, not your address, not the result, not the time. This page explains how that is arranged and where the boundary of it lies.

The counter

One number goes up per scan, along with how many came back strong, weak or insecure. That is the whole record. It is written to a file so a restart does not reset it, and the file reads like this: 

{"scansTotal":87412,"strong":2100,"weak":35000,"insecure":50312,"since":"2026-08-10"}

Two scans a second apart and two a month apart leave the same trace. There is no ordering, no timing, and nothing that distinguishes one from another. It is shown at the foot of every page because a number nobody can trace back to a person demonstrates the claim better than the claim does.

The figure served to a browser stands still for a minute at a time. A counter holds no timestamps, but a counter anyone can poll is a clock: reading it every second would turn "five scans" into "a scan happened at 14:32:08", which whoever holds the other end of that connection could line up against their own records. Freezing it to the minute makes the comparison useless.

No request logs

Nothing about a request is written anywhere: not the hostname you submitted, not your address, not what came back. This is enforced by there being no code that could write it, and a test fails if any appears.

Go's HTTP server writes a line to standard error when a handler panics, and that line contains a client address. The logger is replaced with one that discards, so the promise survives a library default rather than depending on it.

Three lines are printed in the life of the process: that it started, that it stopped, and a failure to write the counter file. None of them describes a request. Under systemd they are collected by the journal, which is where a claim of no logging at all would stop being true — so the claim made here is the narrower and exact one.

Below the service, the operating system keeps its own records, as it does on every machine. The firewall counts packets, the SSH daemon logs administrative access, and the kernel notes packets arriving with a forged source address; that last one holds addresses, and it is kept because a service that could not see an attack on itself would be asking you to trust an operator who is not watching. None of it can say which host you asked about. That is only ever known inside a process that does not write it down.

Your address

Held in memory only, to enforce a rate limit, and dropped about three minutes after your last request. It is never written to disk and never appears in a response.

That figure is arithmetic rather than a policy. An allowance refills completely in a minute, twice that is the point past which keeping the address changes nothing, and the sweep that removes it runs once a minute. A test checks the number against the same calculation the code uses, so this page cannot drift away from what the service does.

For IPv6 the limit applies to the network block rather than the exact address, because a single subscriber is normally given a whole block and can present a new address for every request.

The hostname you submit

Sent in the request body, not in the address bar. A hostname in a URL is written to your browser history, to the referrer of anything the page loads afterwards, and to the access log of every proxy between you and here. Undertaking not to record it while putting it in a URL would hand the record to everyone else instead.

There is a limit on how often any one host is checked, which needs to recognise a repeat without keeping the name. The hostname is hashed with a key generated when the process starts and never written down, then cut to twelve bits — about four thousand buckets for every hostname that exists. Billions of names share each one. The limit works; the name is not there to find.

No third parties

No analytics, no fonts loaded from elsewhere, no content delivery network, no tag of any kind. The page loads one stylesheet and one script, both from this server. There is nothing embedded here that could report your visit to anyone, which you can confirm in your browser's network panel or by reading the source.

Cookies

None. Nothing is stored in your browser at all.

Where this runs

On a rented server in Frankfurt. As with any hosted service, the network provider carries the traffic and can see that connections are made, including the ones this service opens when it checks a server on your behalf. That is true of every scanner anywhere, and it is not something this project can remove.

What it can do is add nothing to it. There are no records here beyond the counter above, so there is nothing to hand over, nothing to seize and nothing to lose in a breach. Anyone who took this machine tomorrow would find a binary, a certificate, and a file containing a number.

Verifying any of this

None of the above needs to be taken on trust. The source is public, the guarantees are listed with the test that protects each one, and the whole thing can be run on a machine you control.
