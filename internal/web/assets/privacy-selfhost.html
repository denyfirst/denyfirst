What this installation keeps

This is a copy of {{.Tool}} somebody runs on their own machine. It keeps almost nothing, and this page says exactly what, from how it was started. If a scan from here reached your server, what a scan does is the section you want.

What is kept

No record of requests. Nothing writes down which name was checked, by whom, or when. The service prints a line when it starts and when it stops, and one when a result could not be kept — naming the operation and the system's reason, never the name.

Your address is held in memory to enforce a rate limit, and dropped about three minutes after your last request. Never written to disk, never in a response.

The names checked are held only as a short keyed hash, for about half a minute to five, so one server is not scanned in bulk. Refusal starts after at least {{.Threshold}} scans of one host in a short window.

Counts of scans and of refusals, by check and by reason, are kept in memory, written to a file only if the installation was started with one, and served at /api/v1/stats. Nothing in them points at a name or a person.

Results: {{if .Keeps}}kept on this machine, because it was started with a results directory: per name and per check, the date, the verdict, the rule set and the rules raised. No time of day and nothing about who asked. They are never served over HTTP.{{else}}not kept. Close the page and the report is gone, unless you saved its JSON.{{end}}

{{if .Verified}}

A verification secret is kept in a file readable by its owner alone. Every record a domain publishes to prove it is theirs is derived from it. Which domains have proven anything is not kept: it is asked again on every scan, so deleting the record ends it.

{{end}}

What a scan does

{{if .Verified}}Only names whose domain publishes this installation's record at _porch-challenge.<domain> are checked; the check page shows the record to publish.{{else}}This installation checks any public name it is given. Without proof, it listens beyond this machine's own loopback address only when its operator said so with -open.{{end}} Private, loopback and reserved addresses are refused whatever is asked.

  • Transport: TLS handshakes at each protocol version, closed as soon as each finishes, on ports that speak TLS from the first byte. No application data is sent.
  • Reach: one GET / over HTTPS and one over HTTP, following redirects a bounded number of times. {{if .ReadsPages}}The final page is read, once, to one megabyte, and only a short list of facts is kept from it.{{else}}No page body is read.{{end}} Query values in a redirect address are not kept in the report.
  • Mail: DNS lookups for the sender policy, DMARC, TLS reporting, MTA-STS, the mail exchangers, their DANE records and signing keys under documented selectors. {{if .Verified}}For a proven domain it also fetches the MTA-STS policy file, and asks each mail exchanger on port 25 whether it offers STARTTLS: greeting, EHLO, STARTTLS, handshake, QUIT. No sender, recipient or message is ever named.{{else}}No mail server is contacted.{{end}} A mail address may be typed; everything before the @ is dropped in the browser and again by the service.

No authentication is attempted, no path is guessed, no exploit or malformed packet is sent. Each host has its own scan budget, whoever asks.

Who else is asked

  • The DNS resolver this machine uses, or the one it was started with, sees every name checked. That is true of anything that resolves a name.
  • The certificate authority named in a certificate is asked for its revocation list. It learns a list was fetched, not which certificate was being looked at, because one list covers thousands.
    • {{if .Verified}}
  • The host itself may be asked for /.well-known/porch-challenge when its domain publishes no record, as the other way of proving a site is yours.
    • {{end}}
  • No certificate transparency log and no revocation responder is asked by this service.

Stopping a scan

This copy is run by whoever runs this machine, not by the people who write {{.Tool}}. To stop scans from it, contact whoever answers for the address they came from. The project can exclude a domain from every future release, but it cannot reach into a copy somebody else is running.

What is not promised

A report describes what a server negotiated at one moment, graded against a published rule set. It is not an audit, not a certification, and not a statement that anything is safe. The software is provided without warranty, under the AGPL-3.0.

Your browser

No cookies, no analytics, no fonts or scripts from elsewhere. Pages load one stylesheet and a small script from this machine, and the ones that check something one more. The only thing stored in your browser is the colour scheme you chose, if you chose one. Nothing is written to the clipboard: a record to publish is selected for you to copy yourself.
