About the scans
from this service.

If you found this page from an address in your logs, this is what happened and what you can do about it. The short version: one TLS handshake, then the connection closed, and no data was requested from your server.

What a scan does

Someone asked this service to check how your server negotiates TLS. To answer that, it opens connections and completes handshakes — the same exchange every browser performs before loading a page.

A single check opens roughly thirty connections over a few seconds: one for each protocol version, several more to work out which cipher suites you accept, and two to see whether you impose your own ordering. Each one is closed as soon as the handshake finishes.

What it does not do

Nothing beyond the handshake. Once the connection is established it is closed immediately, without sending a single byte of application data. Your home page is not requested. No path is tried, no header is sent, no request of any kind is made.

  • No authentication is attempted. No credentials exist here to try.
  • No vulnerability is tested for and no exploit is sent. Only a standard client hello.
  • No administrative path is probed, because no HTTP request is made at all.
  • No malformed packets are constructed.
  • Only ports that speak TLS from the first byte: 443, 8443, 465, 636, 990, 993, 995 and 5061. Nothing else is dialled, so this cannot be used as a port scanner.

Everything the report contains — your certificate chain, the suite that was negotiated, whether a staple was present — is what any client receives when it connects to you. None of it required asking for anything.

Why more than one connection

A server does not announce what it supports; it answers what it is offered. Finding out whether an obsolete protocol version is still accepted means offering it and seeing what comes back. That is why the answer is trustworthy, and it is also why the check is not a single connection.

Load on your server

Each host has its own budget here, independent of who asks. Once a host has been checked twice, further requests for it are refused for a while, even if they come from different people. That limit exists so that this service cannot be aimed at one server in bulk, whether by accident or on purpose.

Stopping it

Write to abuse@denyfirst.dev from an address at the domain, or from one listed in its WHOIS or security.txt, and it will be excluded. No explanation is needed. A reply within two working days, and the exclusion applied before the reply.

The same address reaches a person for anything else: an unexpected pattern, a question about what was sent, or a request for the exact timing so you can match it against your own records.

Identifying this service

Connections come from addresses that resolve to scanner.denyfirst.dev in reverse DNS. That is deliberate: a scanner that hides is a scanner nobody can ask about.

The source is public and there are no dependencies to audit beyond Go itself. If you want to confirm that the description above matches what the code does, read it — the whole exchange is in internal/tlsprobe.
